AgentShield 使用说明

适用版本：2026-09-26 当前本地实现。建议普通用户先阅读第 1–5 节，开发者与安全人员继续阅读第 6–10 节。

AgentShield 提供 Agent Skill 安全审查、六种红黑攻防仿真，以及本机系统与网络体检。场景涵盖公共 Wi-Fi、恶意 Skill、办公内网、身份会话、Web/API 和依赖供应链。黑方代表黑客，红方代表白帽。当前可使用已配置的私有 Qwen 模型；使用这些功能不需要先准备 DGX Spark。

2. 启动与关闭

如果页面已经能打开，无需再次启动服务。否则在终端执行：

cd "$HOME/myProjects/agent-shield"
.venv/bin/python 04_web/app.py --open

浏览器会打开 http://127.0.0.1:8787/。终端显示 AgentShield web → ... 说明服务开始监听。保持该终端运行，关闭服务时在终端按 Ctrl+C。

当前目录已配备主程序环境 .venv 和 NVIDIA 专用环境 .venv-skillspector。前者用于网页、本地规则和演练，后者用于 SkillSpector。不要把两个环境互相覆盖；迁移到新机器时，NVIDIA 依赖安装见 集成安装说明。本机系统检查目前主要适配 macOS。

若默认端口已被其他程序占用，可以另选端口：

.venv/bin/python 04_web/app.py --port 8788 --open

此时本文所有网页链接中的 8787 应改为 8788。服务默认仅监听本机 127.0.0.1；把链接发给别人不会让对方访问到你的页面。

网页右上方可切换浅色／深色主题，以及使用 HOLO ON / OFF 开关控制全息装饰。LIGHT 和 DARK 模式的填色按钮均使用黄色配黑字。选择会保存在当前浏览器，跨页面保持；关闭装饰不影响攻防结果与功能。HOLO 开启时，背景显示静态、低对比度的立体方柱，不显示跟随鼠标的光斑或纹理。鼠标悬停时元素保持原位，只加深阴影，按钮按下时下沉，点击页面空白处会出现扩散波纹。长报告和攻防日志也保持静止，只增强阴影；滚动、拖选文字时会收起跟随效果。触屏仅保留按钮按压反馈。系统启用「减少动态效果」时，关闭跟随、位移和波纹，保留静态边缘层次。

所有页面顶部都有「返回」和「首页」，下方可前往体检、攻防演练、Skill 审查和使用说明。顶栏滚动时保持可见，手机端点击「导航」展开功能入口。返回会优先回到刚才的站内页面，并恢复滚动位置和检查范围、场景防护等选择；直接打开报告时，会返回对应的体检或 Skill 审查页面。返回不会重新执行检查，也不会恢复上一轮演练事件。面包屑显示当前位置，设置入口固定在顶部。导航按钮不再下沉或倾斜，开始检查等操作按钮保留按压反馈。

3. 配置私有模型

现有项目已经配置模型，正常使用时无需重新输入密钥。

  1. 在首页或报告页点击「设置」。
  2. 核对 API base_url、模型和 max_tokens。地址必须包含 /v1，不要填写完整的 /chat/completions 路径。模型名称必须与服务端提供的名称一致。
  3. 只有需要更新密钥时才填写 API key；留空会保留已保存的密钥。
  4. 点击「保存」。重新打开设置，再点「测试连接」。测试读取的是已保存配置，不是输入框中尚未保存的内容。
  5. 如需验证 NVIDIA 语义分析兼容性，再按第 5 节完成一次实际扫描。一次普通聊天连接成功，不等于完整分析节点都能成功。

字段示例（占位值，不能原样使用）：

字段 填写示例或含义
API base_url http://你的模型服务器:端口/v1
API key 你的服务密钥；本说明不保存真实密钥
模型 当前使用 Qwen3.8-27B；换服务后按实际模型名称填写
max_tokens 当前默认 2500；控制输出长度，不是模型参数量
Ollama URL / 模型 可选的本机备用服务；没有部署时不用配置

配置保存在项目根目录 config.json，保存时设为仅当前用户读写。共享项目时使用 config.json.example，不要发送真实配置文件。

各功能的降级方式不同：

功能 模型不可用时
六种场景的规则演练 均可完整运行
NVIDIA 静态审查 仍可运行，不调用模型
NVIDIA 语义审查 明确显示失败或覆盖缺口；不会用模板冒充语义分析成功
演练「私有模型 · 红黑复盘」 提示复盘未完成，已生成的规则演练结果保留
本地规则报告的文字解释 按配置尝试兼容 API、Ollama，最后可使用模板

高级用户注意：通用解释客户端支持 OPENAI_*、OLLAMA_* 环境变量覆盖；NVIDIA 子进程适配器读取项目配置并剥离继承的提供方配置。遇到不同入口调用了不同模型，先检查启动终端中的相关环境变量。

红黑双方使用不同模型

打开顶部「设置」，主模型下方有黑方与红方两组设置。默认勾选「沿用主模型」；取消后可单独填写 API 地址、模型名称、密钥和 max_tokens。保存后再点对应的测试按钮。空密钥输入会保留该角色原先的密钥；换接口时需重新填写密钥，或勾选清除密钥用于免密接口。独立配置不会继承主模型密钥，也不会在失败时切换到其他模型。

双方配置用于智能体行动和规则演示后的文字复盘，智能体模式要求模型支持 OpenAI 兼容的 tools 工具调用。它们默认继承主模型的 API 配置，不继承 Ollama 兜底。

4. 使用左右分屏攻防演练

4.1 完成第一轮

  1. 打开 红黑攻防演练，在「演练场景」中选择「公共 Wi-Fi 同网攻防」。
  2. 展开「场景防护设置」，选择「日常配置」。也可以先保留默认设置。
  3. 点击「开始实时演练」。页面会进入演练工作区，锁定本轮配置。
  4. 左侧黑方显示同网观察、路径尝试和四个攻击目标的结果；右侧红方显示对应监测、虚拟加固和正常业务检查。
  5. 在「运行方式」选择智能体或规则演示。智能体会依次显示模型决策与工具结果；规则演示按初始对攻、加固和复测顺序展示。
  6. 出现「演练完成」后，使用「初始对攻」「修复后复测」切换记录，比较同一目标的变化。

默认选择「红黑智能体」：模型分别观察环境、选择本方工具、读取结果并继续行动，每方最多 4 次决策。黑方不能改防护，红方不能调用攻击工具；双方不共享内部对话。左侧显示黑方选择，右侧显示红方响应，易读视图给出操作摘要，专业视图保留参数和工具结果。模型连接失败会显示未完成，不改用固定流程代替。

若选择「规则演示」，系统先计算固定流程，再逐条播放。两种模式都只操作合成环境，不发送攻击报文。上方前后指标是裁判检查所有预设目标的结果，不是模型实际尝试的成功率。

4.2 三种配置会看到什么

下表是选择「规则演示」时，公共 Wi-Fi 场景当前规则版本的预期结果，目标总数固定为 4：

配置 初始黑方达成目标 红方修复后达成目标 修复后业务检查
薄弱配置 4/4 0/4 2/2 通过
日常配置 1/4 0/4 2/2 通过
全面加固 0/4 0/4 1/2 通过

全面加固开启客户端隔离，会影响同网授权共享协作，所以业务检查只有 1/2。这个场景用于说明防护可能带来的业务代价；“攻击目标为零”不等于所有正常功能都保持可用。

四个目标是：未授权共享访问、明文流量泄露、DNS 重定向、伪造认证页诱导。HTTPS 或 VPN 并不自动解决所有目标，例如用户主动向假认证页提交账号，需要身份核验措施。

4.3 调整防护开关

开关 在当前场景里的含义
访客设备隔离 阻断同热点客户端互访，同时影响同网共享协作
共享访问认证 拒绝匿名读取，保留授权账号使用共享
ARP 欺骗防护 假设网关绑定校验有效，阻止模型中的伪造绑定路径
严格 HTTPS 仅使用 HTTPS，并在证书验证失败时停止连接
可信全隧道 VPN 假设流量与 DNS 都走可信隧道；不改变本地共享权限
核验认证页身份 拒绝向未核验域名提交演示账号
开启红方监测 记录尝试并告警；开启监测本身不会阻断攻击

这些开关只影响虚拟场景，不会修改电脑、路由器或热点的真实设置。红方修复阶段也是虚拟策略变更。

4.4 看进度、停下来与查看证据

  • 跟随最新事件：开启时两侧自动滚动到新记录；关闭后可以停留阅读旧事件。
  • 停止演练：中止当前事件流；智能体正在进行的模型请求返回或超时后结束，再停止后续动作。保留已收到的记录；本轮标为未完成，完整导出与模型复盘不可用。再次点击开始会建立新一轮展示。
  • 阅读深度 → 易读：只显示行为、影响与结果。
  • 阅读深度 → 专业证据：额外显示判定字段和证据 JSON。右侧记录中的“对应黑方”指出同一阶段内的关联事件。
  • 专业视图 · 判定规则与证据 JSON：运行中显示已收到事件，完成后显示完整结果。
  • 私有模型 · 红黑复盘：仅规则演示完成后可用，分别请求模型解释黑方和红方行为。智能体模式已经逐步给出行动目的和工具结果。模型解读不修改胜负与计数。
  • 导出完整证据 JSON：把本轮结果下载到浏览器下载目录；若本轮已完成模型复盘，也会包含该复盘文本。

修改场景设置会清除页面中的上一轮结果；需要留档时先导出。演练结果主要保存在当前页面，刷新页面前也应先导出。

当前版本通过手动阅读深度切换与展开证据适配不同用户，尚未实现经过验证的“自动识别用户专业程度”。

4.5 恶意 Skill / 提示注入

在「演练场景」中选择「恶意 Skill / 提示注入」，或直接打开 Skill 攻防场景。页面会替换拓扑、策略开关和场景前提；运行中不能切换场景。切换会清空当前页面结果，先导出需要保留的记录。

黑方四个预设目标分别是：越权读取工作区外的演示凭据、把已取得的演示凭据外传、诱导高权限工具动作、篡改受保护的最终报告。红方检查同一请求在修复前后的策略结果，并检查正常文档整理和报告发布。

配置 初始黑方达成目标 修复后黑方达成目标 修复后业务检查
薄弱配置 4/4 0/4 2/2 通过
日常配置 2/4 0/4 2/2 通过
全面封锁 0/4 0/4 0/2 通过

本场景的七个开关是文件访问限定工作区、外发目标白名单、工具最小权限、敏感操作人工确认、独立授权校验、工具行为审计、停用全部工具。「全面封锁」把所有工具停用，所以正常业务也无法完成；日常配置与自动虚拟修复展示的是保留业务的另一种选择。

理解结果时注意：外传依赖先取得合成凭据；单独禁止外发不解决本地越权读取；开启审计只增加记录；人工确认假设用户拒绝异常请求，独立授权校验假设由模型外的工具代理正确执行。这些都是当前规则模型的前提，不是对真实系统防护效果的保证。

页面中的「打开 NVIDIA 样本审查」可跳转到植入漏洞样本的官方扫描入口；从该页「Skill 攻防演练」可以返回。两类功能目前通过导航衔接：本演练使用固定合成用例，不会读取某份 NVIDIA 报告并自动生成攻击，也不会把扫描发现直接算作攻击成功。

4.6 新增四种攻防场景

在页面顶部「演练场景」切换，或打开下表入口。每个场景都有四个攻击目标、两个业务检查，支持相同的左右分屏、停止演练、修复前后比较、专业证据、JSON 导出与私有模型复盘。

场景入口 黑方尝试 红方重点 日常配置：初始 → 修复后
办公内网横向移动 匿名共享读取、凭据复用、远程服务修改、文件外传 共享认证、各主机独立凭据、管理面分区、最小权限、出网白名单 2/4 → 0/4，业务 2/2
钓鱼与会话盗用 诱导提交密码、密码登录、失窃会话重放、邮箱导出 链接核验、抗钓鱼认证、会话绑定与撤销、敏感导出审批 2/4 → 0/4，业务 2/2
Web / API 越权访问 他人记录读取、批量导出、管理写入、异设备令牌重放 对象鉴权、功能鉴权、导出范围与令牌绑定 3/4 → 0/4，业务 2/2
依赖供应链投毒 来源不符的更新准入、钩子许可、构建资料外传、异常产物发布 批准来源与哈希、禁用安装钩子、构建出网与发布审批 3/4 → 0/4，业务 2/2

展开「本轮攻击目标与前置条件」可以先了解攻击路径。新增场景中，上游目标未达成时，下游显示「前置未满足」，不会伪造一次已经发生的请求或检测告警。例如：内网远程登录失败后，远程服务修改不再触发；阻止供应链钩子后，依赖该钩子的外传和发布不会触发。

建议尝试的对比：

  • 办公内网：薄弱配置只开启「外发目标白名单」，可以阻止外传，但共享读取仍可能成功。
  • 身份会话：只开启「抗钓鱼多因素认证」，可以阻止本用例的密码登录，但预先失窃会话需要单独绑定或撤销。
  • Web/API：只开启「管理功能权限校验」，不等于已经阻止普通账号读取他人对象。
  • 供应链：只开启「发布产物独立审批」，能阻止发布，但更早的构建资料外传仍可能成功。

四个新增场景的「薄弱配置」均为 4/4 → 0/4、业务 2/2。「全面封锁」会同时开启应急停用措施：内网断网、暂停账号、关闭 API 各使业务降为 0/2；冻结依赖更新使业务降为 1/2，因为已部署应用仍可提供服务。自动修复不会擅自解除这些应急开关。

所有结果均以场景前提为限。例如，来源校验不覆盖可信发布者失陷；会话防护假设服务端逐次校验有效；内网场景从已有失陷终端开始，不展示真实入侵方法。新增规则没有接入真实靶场或 NVIDIA 动态沙箱。

5. 使用 NVIDIA Skill 安全审查

5.1 从内置样本开始

  1. 打开 NVIDIA Skill 审查。
  2. 在「选择项目样本」中选择「植入漏洞样本」「加固样本」或「普通样本」。
  3. 第一次使用建议不勾选「添加私有 Qwen 语义分析」，先验证静态扫描。
  4. 点击「开始官方引擎审查」，完成后点击「查看完整报告」。
  5. 需要模型分析时，再勾选语义分析并运行一次。所选样本内容会发送给已配置的私有模型。

网页入口目前仅允许三个内置合成样本。扫描自己的目录需使用第 7 节命令行入口，不支持在网页上传目录、输入远程 URL 或任意目标地址。

本机曾测得三个样本静态扫描约 1.2 秒、语义扫描约 20–82 秒；这是历史单次测量，不是时限承诺。当前整体扫描超时上限为 240 秒；网页一次仅允许一个 NVIDIA 扫描任务。

5.2 先看状态，再看分数

状态 含义 应当如何理解
已完成所选扫描范围 / complete 请求的分析范围完成 可以审阅发现；不等于样本安全或可以直接安装
部分完成 / partial 存在覆盖缺口、模型未实际完成等情况 查阅覆盖说明，不作完整通过结论
扫描失败 / failed 上游执行失败 已留下的线索可供排查，不能当作成功扫描
页面提示扫描未完成或超时 未产出可用完整报告 在 reports/ 对应目录查看 failure.json（如已生成）

启用语义分析后，还要查看“成功/尝试调用”与覆盖范围。对当前三个小样本，一次完整语义扫描曾达到 5/5；不同输入可能具有不同的分析工作量，不应把这个数当成所有 Skill 的固定门槛。

5.3 两种分数不要混读

报告项目 方向 来源
AgentShield 本地健康分 越高越好 本地规则的确定性扣分
NVIDIA SkillSpector 风险分 越高风险越大 官方引擎对本次静态/语义线索的评估

例如本地健康分 100、官方风险分 58 可以同时出现：它们使用不同规则与分析范围，不能相加或互相替代。名为“加固样本”也不保证官方语义分析没有新增线索。

查看一项发现时，依次读：风险说明、文件与行号、原始规则 ID / finding_id、修复建议，以及它属于静态观察还是模型线索。当前扫描不会执行样本脚本，模型指出的风险尚不等于动态漏洞已复现。

6. 读取、导出与分享报告

首页列出已保存的扫描报告。打开报告后，可下载 HTML、Markdown、JSON 与原始数据；NVIDIA 区域还可单独下载「官方原始 JSON」。

普通用户建议先看最该处理的问题及解释，再展开细节。专业人员可进一步核对原始 finding_id、文件位置、输入哈希、组件版本、覆盖边界和模型调用记录。

NVIDIA 扫描通常在 reports/nvidia-日期时间-随机后缀/ 生成：

文件 用途
report.html 可直接用浏览器打开的报告
report.md 便于编辑、提交或归档的文本报告
report.json 含本地与外部评估信息的组合报告
results.json 扫描结果及相关元数据
skillspector.json NVIDIA 官方原始结果，保持原文
io-policy.json 扫描子进程的网络与进程约束事件计数
model-calls.json、model-errors.json 模型分析节点状态及经过限制的错误诊断
failure.json 某些启动失败或超时情况下的失败信息

失败任务不一定拥有全部文件。目录中的哈希用于核对内容一致性；来源签名另行验证。新报告会显示未签名、验证失败、已通过或未完成，旧报告保留原来的未验证状态。签名通过仍需安全审查。

如果将导出的 HTML 拷贝到别处并希望其中的原始结果下载链接仍可用，应把同目录 skillspector.json 一并保留。演练 JSON 与扫描报告是不同产物，前者通过演练页面单独导出。

报告可能包含被测 Skill 的源代码片段和路径；体检报告可能包含本机或网络信息。分享前检查具体内容，不要连同 config.json 或真实密钥一起发送。

7. 专业用户：审查自己的 Skill

在项目根目录执行以下命令，把示例路径替换为实际目录；路径含空格时保留引号。

# 官方静态审查
.venv/bin/python 05_skill_eval/nvidia_scan.py --skill "/你的目录/my-skill"

# 官方静态审查 + 私有模型语义分析
.venv/bin/python 05_skill_eval/nvidia_scan.py --skill "/你的目录/my-skill" --with-llm

输入目录必须包含 SKILL.md，且不能包含符号链接。当前上限为 1000 个文件、单文件 10,000,000 字节、总计 50,000,000 字节。输出中的 report 字段给出报告目录名。

如要指定报告目录，可添加 --out reports/my-review-01，该目录必须尚不存在。API 或命令返回的 ok: true 仅说明产出了报告；是否完成仍应以 status 与覆盖信息为准。

对自己的源代码使用 --with-llm 前，确认配置的端点就是预期接收方。静态模式不调用模型；适配器限制 Python 网络访问，OSV 在线漏洞查询也会受到限制，应保留相应覆盖说明。

只运行 AgentShield 本地规则并生成模板报告，可以使用：

.venv/bin/python 02_scan/cmd_scan.py \
  --skill 06_samples/vulnerable-skill --no-ai \
  --out reports/manual-example/results.json

.venv/bin/python 03_ai/report.py \
  --input reports/manual-example/results.json --no-narrative

这组命令不调用 NVIDIA 引擎或模型。示例输出目录固定，重复运行会覆盖其中同名文件；留档时换一个目录。若省略 cmd_scan.py 的 --out，它会把 JSON 打印到终端，而不会自动生成完整报告目录。

8. 本机体检与智能体助手

首页或报告顶栏的「体检本机」先进入独立的范围选择页，不会立即启动检查。默认勾选本机系统，局域网扫描需要自行勾选。点击「开始体检」后，页面持续显示运行状态；完成后点击「查看本次体检报告」。报告页提供「返回体检」和「返回首页」，不再依赖点击品牌名称寻找出口。检查会尝试按现有模型设置生成文字解释。当前系统检查主要针对 macOS，包括防火墙、磁盘加密、自动更新等。网络探测会受系统权限、可用工具、设备是否响应以及网络策略影响；未发现设备或端口不证明没有风险。

本次编写说明时发现，网络模块的 IPv4 探测地址拼接存在缺陷，部分端口结果解析也需要维护者复核。因此当前建议保留网页默认的纯本机检查，也可使用下方命令行；网络扫描范围修正前，不把「体检本机」输出视为可靠的完整局域网资产清单。

只检查本机系统，不进行局域网扫描时，使用命令行：

.venv/bin/python 02_scan/cmd_scan.py --sys \
  --out reports/system-example/results.json
.venv/bin/python 03_ai/report.py \
  --input reports/system-example/results.json --no-narrative

首页和报告页右下角的盾牌按钮，或快捷键 ⌘⇧A，可打开智能体助手。可以尝试：

  • “用普通人能懂的话解释最近报告中最重要的问题。”
  • “这条发现的证据是什么？哪些部分只是推断？”
  • “给出修复建议，并说明可能影响哪些正常功能。”

本地规则发现旁的「解释（大白话）」「帮我操作」可用于展开解释或修复步骤；NVIDIA 区域以其独立发现详情与修复建议为准。当前修复入口主要提供步骤与建议命令，不能把显示建议理解为已经修改了系统，也不要把演练的虚拟加固理解为真实热点已修复。

9. 常见问题

现象 处理方法
页面无法访问 确认启动终端仍在运行，检查地址和端口；自定义端口时同步修改链接
启动提示端口占用 先判断原服务是否已经可用；或用 --port 8788 启动，避免重复启动同一端口
更改模型后测试还是旧配置 先保存，再重新打开设置测试；通用客户端还可能受环境变量覆盖
测试连接失败 检查能否访问模型所在网络、base_url 是否含 /v1、密钥与模型名称是否正确；再用实际扫描验证
静态成功，语义分析失败 查看模型节点成功数、覆盖范围及失败记录；模型负载、超时和结构化输出兼容性都可能影响结果
提示组件未安装或版本不符 按 NVIDIA 集成说明安装专用环境并核对锁定版本，不要直接改哈希来跳过检查
演练提示另一场正在展示 关闭其他演练流或停止后稍等再试；同一服务当前只允许一条演练流
停止后没有完整导出按钮可用 这是未完成的一轮；重新开始并等待出现「演练完成」
攻击被阻断却仍有红方告警 监测记录的是尝试，告警不等于攻击成功；也不等于告警本身完成阻断
全面加固或封锁后业务未全部通过 隔离、停用工具、断网、暂停账号或冻结更新可能影响业务；查看右侧业务裁判记录
两个风险分看起来矛盾 本地健康分越高越好，NVIDIA 风险分越高风险越大；分别阅读各自发现
报告没有出现在首页 本地命令只输出 results.json 时还需生成报告；失败目录可能没有 report.json；部分早期失效集成报告已被标记并隐藏

10.2 推荐演示顺序

推荐的演示顺序：

  1. 用薄弱配置展示左右分屏，观察 4 个攻击目标。
  2. 看红方虚拟加固及同场景复测，确认正常业务仍可用。
  3. 展开专业证据，说明每个结果有对应规则与合成事件。
  4. 运行一次 NVIDIA 静态审查，展示官方原始 JSON、版本和覆盖范围。
  5. 私有模型可用时展示语义分析或红黑复盘，说明模型与规则各自负责什么。
