# 四种新增攻防场景

日期：2026-09-26。实现方式：固定合成用例、确定性规则裁判、左右分屏事件展示。黑方是黑客，红方是白帽。与已有公共 Wi-Fi、恶意 Skill 场景合计六种。

## 场景与预期结果

每个场景包含四个攻击目标、两个业务检查。下表为日常配置的规则结果；计数不是实网成功率。

| 场景 ID | 场景 | 初始 → 修复后 | 修复后业务 | 全面封锁业务 |
|---|---|---|---|---|
| `office_lateral` | 办公内网横向移动 | 2/4 → 0/4 | 2/2 | 0/2 |
| `phishing_identity` | 钓鱼与会话盗用 | 2/4 → 0/4 | 2/2 | 0/2 |
| `api_authorization` | Web / API 越权访问 | 3/4 → 0/4 | 2/2 | 0/2 |
| `dependency_supply_chain` | 依赖供应链投毒 | 3/4 → 0/4 | 2/2 | 1/2 |

薄弱配置四种场景均为 4/4 → 0/4，业务 2/2。全面封锁开启所有开关，攻击目标为 0/4；供应链冻结更新仍允许已部署应用服务，因此保留一项业务。

## 攻击依赖与防护边界

- 办公网：共享读取 → 共享文件外传；远程登录 → 修改受保护服务。两个分支独立。出网白名单不阻止本地读取；各主机独立凭据阻止本场景中的本地密码复用。
- 身份：密码采集 → 新登录 → 邮箱导出；预先失窃会话重放为独立分支。抗钓鱼认证不替代会话撤销；暂停账号也不能阻止用户向假页面提交合成密码。
- API：对象越权 → 同批记录导出；管理写入、令牌重放各为独立用例。对象权限、功能权限与令牌绑定不能相互替代。
- 供应链：不可信更新准入 → 安装钩子许可 → 外传／异常发布。发布审批不能追溯阻止更早的外传。批准来源校验不覆盖受信发布者失陷。

前置目标未达成时，下游结果为 `skipped`，`attempted=false`、`detected=false`；界面显示「前置未满足」。这种目标仍计入固定的四个目标，但不计为已触发尝试。监测只改变告警，不改变成功条件。专业证据含前置结果、关联事件 ID、生效策略和判定规则。

自动修复只增加场景内的针对性防护，保留用户已经设置的应急封锁；不会擅自恢复断网主机、暂停账号、已关闭 API 或被冻结的更新。正常业务校验采用单独的授权用例，不将攻击未达成直接记为业务成功。

## 实现入口

- `08_arena/extended_scenarios.py`：声明式场景和共享依赖判定引擎，无文件、网络、进程操作。
- `08_arena/simulator.py`：统一注册、参数校验、调度，兼容原有场景和 API。
- `/api/arena/scenarios`：六个场景目录；`/run`、`/stream`、`/review` 继续共用已有契约。
- `/arena?scenario=<场景 ID>`：深链接；场景下拉框自动读取目录。运行时锁定场景，切换清空上一轮结果。
- 「本轮攻击目标与前置条件」：运行前说明目标与依赖；专业视图、阶段筛选、导出沿用现有界面。
- 模型复盘仍使用分别隔离的黑方、红方上下文，输入为合成结果，不能更改裁判或调用工具。

这些场景没有调用 NVIDIA 动态沙箱。NVIDIA SkillSpector 保持在独立样本审查入口，不将静态发现算作攻击结果。
