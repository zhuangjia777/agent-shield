# 公共 Wi-Fi 红黑演练：首版实现与验证

日期：2026-09-24。黑方＝黑客，红方＝白帽。当前没有 DGX Spark，使用现有私有 Qwen3.8-27B 开发。

## 已实现的交付

从首页“红黑攻防演练”或 `http://127.0.0.1:8787/arena` 进入。选择薄弱、日常、全面加固配置，或逐项调整七个防护开关。点击“开始演练与修复复测”，查看同一场景的进攻、修复与复测结果，支持 JSON 导出。结果由纯函数规则引擎计算，没有执行 shell、调用扫描器或发送攻击报文。

这是**确定性规则仿真**，适合讲解、产品交互和裁判契约验证。合成事件不是抓包、漏洞利用或实网证据；不能用它证明真实防护有效或攻击模型强弱。时间线的“模拟步”不是实际延迟。四个目标的计数不进入现有 Finding 风险分。

| 路径 | 黑方预设目标 | 模型中的阻断条件（任一成立） |
|---|---|---|
| 未授权共享访问 | 读取合成共享文件 | 客户端隔离、共享认证 |
| 明文流量泄露 | 取得合成 HTTP 会话标记 | 客户端隔离、ARP 校验、严格 HTTPS、可信全隧道 VPN |
| DNS 重定向 | 业务请求到达假站点 | 客户端隔离、ARP 校验、严格 HTTPS、可信全隧道 VPN |
| 伪造认证页诱导 | 用户主动向独立假站点提交演示账号 | 用户核验页面身份并拒绝提交 |

默认“日常配置”已启用共享认证、HTTPS 和监测，黑方只达成钓鱼诱导这一预设目标。薄弱配置是人为构造的教学反例，不代表所有公共 Wi-Fi 的默认情况。

## 前提、红方权限与业务取舍

黑方已接入同一热点，未控制网关、终端或 CA。共享设备与访客处于同一二层域；ARP 防护代表正确配置且实际生效的绑定校验。VPN 代表已建立、包含 DNS、无旁路的可信全隧道。不存在“只要在同一 Wi-Fi 就能解密 HTTPS”的规则。

DNS 重定向事件区分 `dns_answer_changed` 和 `request_reached_fake_service`：DNS 可以被改变，但严格证书校验使业务请求未达成黑方目标。钓鱼事件是已呈现的诱导链接与用户决策分支，不依赖本地客户端互访；TLS 加密和 VPN 不会使恶意网站自动变可信。该设计参考 [FTC 公共 Wi-Fi 指南](https://consumer.ftc.gov/articles/are-public-wi-fi-networks-safe-what-you-need-know)，具体判断公式属于本项目假设。

客户端隔离用于限制同 WLAN 客户端通信，实际范围受设备配置影响，见 [Cisco Peer-to-Peer Client Support](https://www.cisco.com/c/en/us/td/docs/wireless/controller/9800/17-4/config-guide/b_wl_17_4_cg/peer-to-peer-client-support.html)。本仿真假定完全阻断这些客户端的互访，因此明确记录“合法本地共享协作受影响”。它不假定普通咖啡店访客拥有修改热点配置的权限，每个修复项显示实施角色。

红方默认修复使用共享认证、严格 HTTPS、核验认证页和监测，保留用户已启用的其他防护，不直接把所有隔离开关全部打开。正常 HTTPS 与授权共享两项业务检查一起复测。开启监测只增加告警，不改变攻击胜负；“检测到”与“阻断”分开记录。传感器覆盖是仿真预设，不声称现实告警能达到 100%。

## 模型与解释颗粒度

“私有模型 · 红黑复盘”调用现有 Qwen API，两次请求分别使用黑方和红方独立上下文。仅提交场景假设、合成结果、修复项与业务检查，不提交真实主机信息或凭据。模型输出经过 HTML 转义，不能修改裁判结果，也不能调用执行工具。模型调用失败保留规则结果，显示可重试错误；不以模板冒充模型回答。

默认展示易读时间线，选择专业证据或展开判定 JSON 后展示规则、证据 ID、前提和状态。模型复盘同时要求普通用户结论与专业解读。这是渐进披露的首版，尚未实现根据用户长期行为自动估计专业程度，也未实现黑方自主选择攻击、红方自主生成补丁的多轮自治对攻。

## 可复核结果

| 配置 | 修复前黑方目标 | 修复后黑方目标 | 修复后正常业务 |
|---|---:|---:|---:|
| 薄弱配置 | 4/4 | 0/4 | 2/2 |
| 日常配置 | 1/4 | 0/4 | 2/2 |
| 全面加固 | 0/4 | 0/4 | 1/2（隔离阻断本地协作） |

上述都是规则推导值，不是实网测量。引擎版本 `wifi-tabletop-1.0`，相同版本和输入产生相同 run_id 与事件。导出包含原始开关、前后事件、证据关联、修复项、业务影响和仿真标识，模型复盘单列。

测试：`tests/arena_simulation.py` 的 11 项测试覆盖全部 128 种策略组合、复测业务不退化、HTTPS/VPN/隔离/监测边界、禁止真实目标参数、无网络/进程调用、模型独立上下文、接口错误脱敏。`tests/config_security.py` 的 3 项密钥保护回归及现有静态评测门禁通过。浏览器验证了薄弱配置的 4→0 与 2/2 业务结果，实际私有 Qwen 红黑复盘返回成功。

## 接口与代码

- `GET /arena`、`GET /api/arena/catalog`：界面与场景说明。
- `POST /api/arena/run`：只接受 `scenario="public_wifi"` 和布尔 `controls`，不接受目标地址、网段或命令。
- `POST /api/arena/review`：由后端重算场景后向模型发送合成摘要，不信任客户端提交的胜负；单次串行复盘锁，避免重复占用模型。
- `08_arena/simulator.py`：无外部依赖的规则与证据契约。
- `04_web/arena.html`、`04_web/arena.js`：拓扑、开关、时间线、复测和导出。
- `04_web/app.py`：路由与模型复盘。

## 私有模型接入状态

当前兼容 API 配置保存在 `config.json`，模型为 `Qwen3.8-27B`，配置文件权限为 `0600`，已被 `.gitignore` 排除。设置读取不返回原始 key，密码框留空保存不会覆盖既有 key。报告和本文不记录 key。

四项合成连通测试（模型列表、JSON 回复、SSE 流、原生工具调用响应）通过，脱敏记录在 `reports/private-llm-check-20260924/compatibility.json`。工具响应测试未执行任何工具。项目原有 ReAct 仍使用文本格式；原生响应兼容不等于 Agent 工具循环已适配。

“私有部署”代表请求发往配置的内网服务，不代表该服务内部无外连；本次没有审计模型服务器。“无审查”也不是实测攻击优势，需在同一授权测试集、预算和规则下比较目标覆盖、有效变体、可复现成功及无效动作比例。本规则仿真不能用于给攻击模型排榜。

## NVIDIA 参赛路线的衔接

当前仿真和 Qwen 不计作 NVIDIA 运行组件集成。独立的 Skill 审查入口现已接入原版 SkillSpector，见 [集成验收记录](nvidia-integration-2026-09-24.md)。来源验签、治理产物和动态沙箱继续按 NVIDIA 生态方案推进；保留引擎身份和原始结果。不要把 OpenShell 当作无线网络模拟器。

动态版本另设隔离靶场：独立网络命名空间/虚拟机中的客户端、共享靶机、网关和黑方，固定镜像与自建合成服务；先证明无桥接到宿主内网、无真实凭据、可回滚，再将真实观察适配到当前证据契约。无线关联/恶意热点属于另一实验层，不用普通容器网络假装实现。DGX Spark 可用后仅迁移模型与兼容运行组件，按实际硬件重新测量性能，不能沿用当前 API 时延冒充 Spark 成绩。

## 左右分屏与事件流（2026-09-24 更新）

`/arena` 已改为左黑右红双列。左侧展示黑客观察、路径尝试及目标结果；右侧展示对应检测、虚拟策略加固和正常业务裁判。四阶段进度、目标计数随事件更新；专业模式展开证据 JSON，完成后可切换初始/复测视图和导出完整记录。窄屏改为上下排列。

新增 `POST /api/arena/stream`，参数与原 `/run` 相同，只接受场景和布尔控制。服务器先用同一确定性引擎计算结果，再按 450 毫秒阅读节奏逐条推送 NDJSON；这是真实的流式展示，但不是实时网络攻击、真实执行时长或动态智能体过程。完整结果最后发送，断流/停止不记作完成，也不允许导出完整结果。单次仅允许一条演练事件流，断开连接后释放名额。

“停止展示”保留已收到的事件；重新开始建立新一轮展示。参数在运行中锁定，避免前后配置混杂。浏览器已验证逐条到达与日常配置最终 1→0、业务 2/2；服务端新增顺序/证据一致性、正常结束、断开释放及非法参数/并发测试。
