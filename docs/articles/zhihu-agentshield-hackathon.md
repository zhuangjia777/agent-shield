# 为黑客松做一个安全 Agent：让 AI 的攻击结果接受独立验证

同一条 SQL 注入请求，开启 WAF 时返回 403；关闭防护后，靶机记录显示管理员登录挑战完成；恢复防护后，再次被拦截。

这是 AgentShield 在 Docker 隔离演练场里的一次实验。准备黑客松项目时，我想验证一个具体问题：当 AI 开始调用安全工具，我们怎样知道它真的完成了任务？

模型可以解释风险，也可以提出操作方案。但一句“攻击成功”或者“已经修复”，不能直接作为结论。于是，我把命令确认、真实执行、工具反馈和独立结果检查串成了一个可观察的流程。

项目已经开源：https://github.com/zhuangjia777/agent-shield

## 一、先看一次真实演练

演练场由三个容器组成：Kali 攻击机、可切换防护状态的 WAF，以及自带测试漏洞的 OWASP Juice Shop 靶机。

演示中，攻击流量经过 WAF 到达靶机。开启防护时，请求被拦截；关闭防护后，重复同一条请求，靶机的挑战记录发生变化；恢复防护后再次复测，观察请求是否重新被拦截。过程中还检查正常业务请求，避免把“所有请求都被挡住”误当成有效防护。

判断依据包括 HTTP 返回结果和靶机 API 中的挑战状态。模型对结果的解释可以辅助阅读，但不能替代这些证据。

仓库 README 提供了这次运行的动图和 2 分 42 秒中文配音视频。视频压缩了模型思考等待时间，阅读时需要与实时运行耗时区分。

演示视频：https://github.com/user-attachments/assets/7d859898-fcee-42a4-bb74-403a42390e1d

这里的攻击只面向本机隔离容器中的测试靶机。它适合验证这个具体环境里的防护变化，不代表对真实生产系统的全面安全评估。

## 二、Agent 的价值，体现在操作与反馈之间

AgentShield 使用 ReAct 式循环：模型观察当前情况，选择工具，接收工具返回，再决定下一步。

例如，用户点击“交给 Agent 一步步带我”后，Agent 先检查演练场状态。如果环境已经存在，就基于当前状态继续；准备执行攻击时，先展示完整命令，等待用户确认；执行后再读取反馈，决定是否检查防护状态或调用裁判探针。

这个过程中，我关注的不是模型说了多少分析，而是每一轮有没有得到可以检查的观察结果：工具是否真正执行，返回了什么，下一步是否与返回结果一致。

目前 Docker 实战由一个 Agent 编排攻击工具与蓝队 WAF 操作。另一个沙盘模式支持红蓝模型各自决策，但工具只修改合成环境。两种模式的执行范围不同，需要分别介绍，不能把沙盘画面当作真实网络攻击证据。

## 三、四个值得讲清楚的设计

### 1. 攻击命令先给人看

每个攻击动作先展示完整命令，得到确认后才执行。用户可以看到目标和参数，也可以取消。对安全工具而言，这一步是交互流程的一部分。

### 2. 隔离需要检查

演练场通过 Docker 网络限制攻击范围，启动过程中检查相关连通性和隔离条件。如果检查失败，就拒绝继续。工具层也限制目标，降低模型生成偏离演练范围的命令被执行的可能。

这些措施有明确的实现边界，不能把它们描述成对所有风险的绝对保证。

### 3. 裁判与模型解释分开

攻击是否命中，读取靶机真实记录；请求是否被拦截，检查响应；防护切换之后，使用同一请求复测。

模型负责解释证据，判定应能由读者沿着日志追溯。这也是我认为安全 Agent 最值得展示的部分：即使不相信模型的自评，也可以检查它的工作。

### 4. 停止按钮必须真的停止流程

开发时发现 Docker 演练页面缺少直接停止入口，于是补上了“停止并清理演练场”。它调用拆场逻辑，反馈清理成功或失败。

仅删除容器还不够。如果旧的 Agent 任务仍在等待确认，它可能在稍后继续操作。因此停止流程还要阻止旧任务重新起场，并协调已经在执行的操作。围绕这些情况，项目补充了后端回归测试和按钮交互测试。

这个小功能提醒我：Agent 产品的完整性，也体现在用户如何暂停、退出和处理失败。

## 四、除了演练，还能做什么

AgentShield 还提供本机安全体检、Skill 静态检查和报告解释。本机检查目前主要适配 macOS；Skill 检查可以查看风险线索与对应证据，并可安装 NVIDIA SkillSpector 做补充审查。

不同检查的结果分别展示，不能简单把不同评分体系加在一起。检查未发现问题，也不等于被检查对象没有风险。

这些入口可以帮助用户从“发现问题”走到“理解问题”，再通过演练观察某项防护的实际作用。

## 五、如何与黑客松的技术验证结合

我希望把参赛准备做成可复现的工程记录：明确问题，给出实验，保留版本和证据，再说明哪些部分还没有完成。

NVIDIA 相关工作中，项目已有 SkillSpector 集成说明与验证记录；README 也补充了在 DGX Spark 上部署 Qwen3.8-27B 或 Qwen3.8-Flash-Next、通过兼容 OpenAI 的接口连接 AgentShield 的参考步骤。

需要明确的是：DGX Spark 目前尚未完成本项目的实机验收，不能把部署文档当作“已经跑通”的结果，也没有可据此公布的性能成绩。

后续实机验证要覆盖一次完整 Agent 任务，并记录模型及量化版本、推理引擎版本、上下文长度、首字延迟、生成速度和峰值内存。Flash-Next 的激活参数量不能直接用来估算完整模型的内存需求，因此应先确认硬件容量，再讨论运行效果。

模型可以部署在 Spark 上，AgentShield 通过本机连接或 SSH 隧道调用它；如果 AgentShield 运行在另一台电脑，系统检查与 Docker 工具仍在那台电脑上执行。模型所在位置和工具执行位置，需要分别说明。

如果你试用，我最希望收到三类反馈：安装在哪一步遇到问题；哪一个 Agent 动作让你看不懂或不放心；最希望增加什么可验证的演练场景。
